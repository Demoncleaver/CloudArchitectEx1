# Serverless Chatbot — AWS Lambda + OpenAI + DynamoDB + Amplify

A serverless chatbot: a static web page hosted on AWS Amplify calls a Lambda Function URL,
which loads recent conversation history from DynamoDB, calls the OpenAI Responses API,
stores the new exchange, and returns the reply with timing data.

## Lambda function

* **Name:** `open-ai-chatbot`
* **Runtime:** Python 3.13, x86\_64
* **Execution role:** `LabRole`
* **Handler:** `lambda\_function.lambda\_handler`
* **Timeout:** 30 seconds (default 3s is too short for OpenAI calls)
* **Environment variables:**

  * `OPENAI\_API\_KEY` — OpenAI secret key (not committed)
  * `TABLE\_NAME` — `chat-history` (default)
  * `OPENAI\_MODEL` — `gpt-4o-mini` (default)
* **Layer:** `openai-layer` (see `layers.txt`)
* **Function URL:** Auth type `NONE`

### API contract

`POST` to the Function URL:

```json
{ "user\_prompt": "What is serverless computing?", "user\_id": "optional-session-id" }
```

Response `200`:

```json
{ "ai\_reply": "Serverless computing lets you...", "openai\_response\_time\_ms": 1510 }
```

|Method / case|Status|
|-|-|
|`POST` with valid body|200|
|`OPTIONS` (CORS preflight)|200 + CORS headers|
|Any other method (`GET`, `PUT`, …)|405|
|Invalid JSON / missing `user\_prompt`|400|
|OpenAI or DynamoDB failure|500|

CORS headers returned on every response:
`Access-Control-Allow-Origin: \*`, `Access-Control-Allow-Methods: POST, OPTIONS`,
`Access-Control-Allow-Headers: Content-Type`.

## DynamoDB configuration

* **Table name:** `chat-history`
* **Partition key:** `user\_id` (String) — one conversation per browser session
* **Sort key:** `timestamp` (Number) — epoch milliseconds, orders messages chronologically
* **Capacity mode:** On-demand

|Attribute|Type|Description|
|-|-|-|
|`user\_id`|String (PK)|Session ID generated by the frontend and kept in localStorage|
|`timestamp`|Number (SK)|Epoch ms when the message was created|
|`role`|String|`user` or `assistant`|
|`content`|String|Message text|

On each request the Lambda queries the partition with `ScanIndexForward=False, Limit=6`
to get the **last 6 messages**, reverses them to chronological order, appends the new prompt,
and sends them to OpenAI. The user message and AI reply are then written as two new items.

## Response-time measurement

* **OpenAI API time** — measured in Lambda around `client.responses.create` with
`time.perf\_counter()`, returned as `openai\_response\_time\_ms`.
* **Total request time** — measured in the browser with `performance.now()` from just before
`fetch` until the JSON response is parsed (network + Lambda + OpenAI).
* The page shows a grouped bar chart per call, the average of each measurement, and the latest
values; all update after every request and live only in the current browser session.
